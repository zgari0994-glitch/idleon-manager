# Idleon Toolbox: what to inspect, why it matters, and what to do next

Reviewed 16 November 2026 against the public **Autiszemo** profile. The upload showed **18 hours old**, so account examples below are findings from that snapshot, not confirmation of the current game state.

This is a decision map for you, Codex, and Claude. Combined into one file on 17 November 2026. This is Toolbox reference material, not a creator transcript or a substitute for the repository's source-priority rules. It covers **56 world pages, 27 Account pages, all 12 Tools pages, Dashboard, Characters, and Wiki**. Every listed root page was opened. Subsections are inventoried where exposed; this is not a claim that every item tooltip, optimizer, character, and saved preset has been exhaustively audited. Top-level Guilds, Stats, and Leaderboards are excluded. Account → My guild is retained only for useful account bonuses; Friends Stats is a gameplay bonus system, not the excluded statistics page.

**Use [the review protocol below](#review-protocol-for-codex-and-claude) whenever doing dailies, choosing a new job, planning an overnight session, or reviewing progression.** This document explains where the evidence lives. The protocol explains how to turn it into recommendations without overlooking things.

Links open your public profile. A fresh signed-in save can expose functionality unavailable in the public view. Inspection and planning in Toolbox do not equip items, change in-game presets, spend currencies, or collect rewards in IdleOn.

Cadence in the tables is a proposed review trigger: **Daily** means check relevance during dailies, not mechanically perform every action daily; **Switch** means whenever changing the character's job; **Goal** means whenever adding a target or changing its priority; **Periodic** means a broader progression audit; **Reset** means the actual system reset/rotation, not necessarily midnight.

## Dashboard: start here

[Open Dashboard](https://idleontoolbox.com/dashboard?profile=Autiszemo)

| Area | Information it holds | How it should help you |
|---|---|---|
| Account alerts | Claims, full capacities, stopped production, affordable upgrades, missing unlocks, attempts, shops and rotations across worlds | Build today's account-specific action list. Open the destination page to confirm each important warning and its prerequisites. Do not substitute a generic daily checklist. |
| Character alerts | Task/setup mismatches, unused points, missing tools/traps, upgrade slots, cooldowns and other character omissions | Identify who needs attention and what to inspect in Characters. A tool-level alert means investigate eligibility, ownership and benefit; it does not mean the better tool is already available. |
| Goals | Material/greenstack goals when configured and supported by the loaded save | Keep future gear, stamps, bubbles, vials and unlocks visible before a shortage becomes urgent. Public-profile goals were unavailable during this review. |
| Timers | Ready actions, cooldowns and reset-dependent opportunities | Order actions by expiry/cap and session length. Distinguish daily, weekly, server and personal timers; communicate actual local deadlines in America/New_York. |
| Alert configuration | Account, character and timer settings, thresholds and visibility | Audit configuration periodically. An absent alert is not proof that a system is healthy. A permissive threshold can make almost everything appear ready. |

The snapshot showed **120 account alerts**, plus character alerts. That is an inbox to triage, not 120 instructions to obey. Assign each consequential alert one outcome: **do now / schedule / goal dependency / intentionally deferred / locked / uncertain**. Explain why deferred alerts can safely wait.

Examples of necessary interpretation: printing at a storage threshold may deliberately feed atoms; farming with a zero harvest threshold is not a recommendation to harvest every plot; a computed Sushi or Button alert does not prove the feature is unlocked.

## Characters: all 16 sections

[Open Characters](https://idleontoolbox.com/characters?profile=Autiszemo). The initial view showed only **5 of 16 sections**. Select **Sections → All** before a comprehensive audit, then inspect every character. Use the character selector/comparison view rather than assuming the first character represents the account.

| Section | Information it holds | Decision it supports |
|---|---|---|
| Stats | Level, location/job, AFK state, combat and other derived stats with breakdowns | Check accuracy, survivability, damage and the output relevant to this job. Diagnose the source of a bottleneck rather than guessing which upgrade helps. |
| Talents | Class and star talents, allocated/current/max levels, available points, saved talent presets and which is in use | Inspect **both saved presets** where available. Match combat, skilling, sampling or class-farming priorities. A talent absent from the active preset may exist in the other one. Check library book potential before prescribing resets. |
| Cards | Equipped cards, card levels, card-set bonus, preset tabs and active preset | Inspect **every available preset**, not just the equipped eight cards. The inspected character exposed seven presets. Label them by purpose and record the actual set bonus separately. |
| Skills | Individual skill levels and relevant efficiency/EXP/AFK breakdowns | Choose who should gather, sample, train or unlock a better tool. Detect neglected characters and compare account mastery goals. |
| Equipment | Weapons, armor, accessories, tools, food and special slots, including upgrade opportunities | Verify what is worn, not merely owned. Compare task bonuses, upgrade stones, tool eligibility and survivability. Inspect tool/food slots as carefully as armor. |
| Obols | Personal and family arrangements | Match the relevant stat to the task and confirm the correct pieces are placed. Protect shared family effects when changing a specialist. |
| Obols Stats | Aggregated obol contributions | Check whether a proposed arrangement actually supplies the intended bonus; avoid evaluating icons alone. |
| Inventory | Each character's carried items and occupancy | Find missing ingredients outside storage, return useful stock, avoid overflowing while farming, and identify items needed for quests or upgrades. |
| Bags | Slot and stack capacities | Explain carry-limited stamp upgrades or overnight losses. A large storage total does not imply a character can carry the required stack. |
| Prayers | Equipped prayers and their effects | Evaluate benefits **and curses**, especially an AFK-duration cap or skill EXP penalty before an overnight/training job. Account passives may change whether equipping is useful. |
| Star Signs | Equipped signs and unlocked/passive context | Match task-specific signs; identify genuinely empty useful slots without confusing passive/unlocked effects with manual selections. |
| Equipped Bubbles | Character bubble assignments | Match the task while accounting for account unlocks/pets such as Sheepie; do not prescribe redundant swaps. |
| Chips | Equipped laboratory chips | Match card doubling, skilling and combat effects; card placement can matter. Verify ownership and who currently holds a chip. |
| Divinity | God links, styles and character progression | Preserve intended minor/link bonuses and EXP goals. Doot changes the decision; it does not justify ignoring this section. |
| Anvil Details | This character's production, points and allocations | Fix missing hammer assignments, allocate points appropriately, prevent capacity loss and support material targets. Cross-check account-wide Anvil. |
| Post Office | Boxes, allocated and unspent points | Apply useful available bonuses to the current role; do not leave large point pools unused without a reason. |

**Preset viewing is not preset switching in the game.** For each important job, record character, purpose, talent preset, card preset, card set, equipment/food, chips, prayers, signs, obols and relevant god/bubble effects. Then verify the resulting in-game rate after the user changes setup.

### Hole cavern checklist

The 18 cavern tabs are **The Well, Motherlode, The Den, Bravery, The Bell, The Harp, The Lamp, The Hive, Grotto, Justice, The Jars, Evertree, Wisdom, Gambit, The Temple, The Fountain, The Bottomless Trench, Crystal Glunko Cove**. Check unlock status before generating a daily action. The reviewed account showed 15/18 unlocked.

| Cavern or control | What to look for / why |
|---|---|
| The Well | Bucket rates, sediments, layer progress, capacities and next opal cost; prevent resource bottlenecks and capped buckets. |
| Motherlode, The Hive, Evertree | Resource/skill progression and available layers or breaks; compare the assigned character's relevant gathering setup and the next unlock. |
| The Den | Encounter difficulty modifiers and progress; prepare combat accuracy, damage and survival before pushing. |
| Bravery, Justice, Wisdom | Ready monument activities, AFK requirements, bonuses and next rewards; schedule appropriate sessions rather than leave readiness ignored. |
| The Bell | Ring/Ping/Clean/Renew modes, rates, readiness and improvements; choose the next useful resource/bonus and avoid capped progress. |
| The Harp | Notes, tune, strings and EXP; direct production toward the upgrade currently blocking progress. |
| The Lamp | Wishes, costs, bonuses and reset options; budget wishes and evaluate resets deliberately rather than treating every affordable wish as good. |
| Grotto | Displayed progression and bonus sources; inspect current unlock and next milestone before assigning a job. |
| The Jars | Capacity, types, rupies, collectibles and enchantments; choose collection/bonus targets and avoid overflow. |
| Gambit | Times, score, thresholds and Summoning doublers; target the next useful reward and allocate unspent doublers. |
| The Temple | Progress and upgrade choices such as search/amplify; spend resources on the current encounter/progression bottleneck. |
| The Fountain | Currencies, fill time, upgrade graph/list and opals; verify unlock before acting on computed timers. |
| The Bottomless Trench, Crystal Glunko Cove | Later cavern progression; retain as explicit locked/unlocked checklist entries. This review did not establish a complete strategy for their later mechanics. |
| Engineer / Bonuses / Measure / Study | Check schematic gates/costs, account benefits, progression measurements and study choices alongside Explore; use these to decide where scarce opals/resources give useful progress. |

## Required starting checks

1. Confirm the account, save/upload age and whether the view is signed-in or public. Never describe an old upload as live state.

## Mandatory task-switch prompt

Whenever recommending a switch—especially drop farming → overnight combat, combat → skilling, or normal play → sampling—include:

1. **Who, where, why, for how long.** Name character, target, objective and stopping condition.
2. **Talent preset and active skills.** Verify points and current/max levels; check class mechanics and library upgrades where relevant.
3. **Card preset and card set.** Evaluate cards and the set separately; consider passive cards, owned levels and chip placement.
4. **Equipment, tools, food and inventory.** Match the role, ensure survival and space, and check capacity for the expected duration.
5. **Prayers, signs, chips, obols, bubbles and divinity.** Check benefits, curses, time caps and account unlocks/pets that remove otherwise necessary swaps.
6. **Validate the result.** Compare the relevant in-game AFK/skill rate or measured active rate after the switch. Restore the intended regular setup after sampling or a temporary job.

Example wording: “Before leaving [character] at Purp Mushroom for [duration], use the verified AFK combat talent/card setup and card set, check AFK kills and survival, remove any incompatible duration cap, and confirm inventory capacity. The target is [remaining kills/materials], so review at [condition/time].” Fill those fields from evidence; do not invent a preset number.

Do not automatically remove every drop-rate card. Choose against the actual objective and compare damage/multikill, AFK gains, EXP and material output. A community build only informs the recommendation when its patch, account stage, ownership and activity match.

## Proactive material planning

Before saying “farm X,” use **Item Browser** to locate it in storage and every character inventory. For gear, use **Item Planner** and recipe/unlock information. For stamps/bubbles/vials, inspect the exact next-level cost, including coins/liquids/carry requirements. Use **Wiki** to confirm sources and dependencies.

Maintain this ledger in Material Tracker when the user's save supports it, or a local file otherwise:

| Goal / priority | Target item or upgrade | Total required | Stored + character-held | Claimable output | Reserved for other goals | Net shortage | Producer / net rate | Estimated ready / review | Unlock / evidence |
|---|---|---|---|---|---|---|---|---|---|
| User goal | Exact recipe/level and quantity | Verified costs | Avoid double-counting | Separate until collected | Protect planned spending | Formula below | Anvil/forge/print/farm/etc. | Include cap/collection assumptions | Source page and save age |

**Net shortage = max(0, target requirement + other reservations − usable owned stock − claimable usable output).** Count each unit only once. If a total requirement already includes other reservations, do not add them again.

**Estimated time = shortage ÷ positive net production rate**, adjusted for downtime, collection caps, competing consumption and acceleration. If net production is zero/negative, recommend a producer/allocation change rather than an invented ETA. Do not include anvil output both as stored stock and claimable production.

Check the chain: goal → exact cost → existing ownership → unlock/carry requirement → source → producer assignment → throughput/cap → review date. This is how future cords, bars, salts and other ingredients become advance warnings instead of last-minute surprises.

## Recommendation standard

Every meaningful recommendation should communicate **evidence → action → benefit → cost/tradeoff → verification/stop condition**. Include exact character and target where applicable. Rank by avoided losses, expiring opportunities, cheap permanent gains and progress toward the user's current goals—not by whichever page was opened last.

Always distinguish:

- Affordable from worthwhile; equipped from owned; claimable from merely satisfying a condition.
- Account-wide kills from character-specific milestones; credited kills from calculator-normalized kills.
- Passive effects from equip requirements; public-view missing data from actual zero ownership.
- Intentional atom production from harmful storage caps; locked features from daily chores.
- Source-supported current strategy from an unverified “meta” label. Compare with Griffy only when stage and circumstances match; otherwise **unknown**.

After the user performs actions, refresh the save and verify that warnings cleared, rates improved, goals advanced and the intended job is active. Keep deferred items with a reason and next trigger. Report unresolved uncertainty plainly.
